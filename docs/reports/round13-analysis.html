What the system is lacking, ranked by what it cost here

Every item is a class of failure any hidden problem can trigger, with the smallest generic change.

G1Oracle latency above the cap, timeout retried identically3 of 4 oracle calls

The fast model streams at ~33 tok/s; a 4–8k-token oracle needs 120–240 s. Correction: the committed config already caps the fast role at 150 s; the 120 s cap this round ran under was a mistake in the scratch config, so "cap below measured latency" is withdrawn. What stands: the model's latency is at or above any cap the budget can afford, a timeout is logged as "no block" and retried with the same prompt at the same cap, and the sequential start adds the solve latency on top.

Change: retry only when the budget covers it, asking for shorter output; stream and abort on a no-bytes stall; restore the concurrent start; author the oracle with a model that returns in tens of seconds; ask for less by defining validate as "reference did not raise".

G2An unclosed code fence destroys a candidateboth runs, c1

llm._unfence strips only a fence with a matching closer. The model opened a fence inside CODE and closed it after END, so the fence line landed in the file and the candidate failed static. Half the pool was lost both times, and c1 was the better candidate both times.

Change: also strip a leading fence line and a trailing bare fence when unmatched. One regex.

G3The sample-specific smoke check is wrong and disables everythingrun B

Six hardcoded inputs for one entrypoint, all missing one tuple level, so every oracle fails all six. With the nesting restored the adjudicator's reference passes all six. The check fired, disabled differential evidence, and left 41 s for nothing. It scores zero on every other problem by construction.

Change: delete it. The generic replacement is examples the SOLVE model writes in its own block, run against candidate and oracle before gating.

G4The prompt's complexity rule does not reach this modelall four candidates

The DESIGN block says to reject any approach that expands a repetition up to 10^18 or scans a flattened layout. All four candidates do exactly that. With a non-reasoning model a prose rule is not a check.

Change: the independent timing gate on a grown input, and a fresh-solve path that hands the model the measured timeout, the input's sizes, and "do not use this approach".

G5Random small inputs do not reach the hard staterun B, and round 10's verdict

Random operation sequences go invalid before a repeat is filled, so a candidate wrong on the whole clause shows 1.3 % mismatch on random inputs and 100 % on the canonical shape. The oracle's gen and the shrinker share the blind spot.

Change: one rule in the oracle and stress prompts: at least half of generated sequences stay valid to the end and drive every bounded quantity to its bound; plus SOLVE-authored examples naming the hardest shape.

G6Skipped steps logged as passedboth runs

Six skipped gate steps print as passed=True; only the status line says nothing was checked.

Change: log skipped explicitly. Cosmetic, but it misleads every reader of the log.

Model capability, stated plainly

Strong model (qwen/qwen3-coder): four independent attempts at this statement, all correct on containers, arrays, defaults and the invalid-operation result, all wrong on repeat, all non-terminating at the limits, zero reasoning tokens, 17–24 s per call. Two attempts per run do not reach the intended algorithm; a re-solve with concrete failure evidence is the only lever left at this model.

Fast model (deepseek/deepseek-chat-v3-0324): three oracles for this problem across rounds 10 and 13, all unusable (constant answer, constant answer, 45 % wrong and crashing on arrays), 106–128 s per call. The self-consistency check does not catch it: reference ran clean on 45/45 of its own gen inputs.

Cost is not the constraint: $0.013–0.016 per run against a $0.50 cap.

What to do next, in order

  1. G2 and G1. Fence stripping, cap and retry, concurrent start. Mechanical, and they lost three of four oracle calls and both first candidates.
  2. Remove G3 and replace it with SOLVE-authored examples; add the G5 rule to the oracle and stress prompts.
  3. G4. The timing gate and the fresh-solve path. The only path to a correct repeat with this model.
  4. Re-run this problem, then the other three focus problems.
